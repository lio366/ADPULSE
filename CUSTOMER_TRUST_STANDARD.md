# ADPULSE — Customer trust and experience standard

Every customer-facing feature must meet these rules:

1. **Clarity:** explain what the feature does, what it does not do, what data it reads, and what action it may take.
2. **Consent:** request only necessary permissions; explain why; let the customer revoke them.
3. **Control:** provide pause, disable, approval, budget caps and an activity history.
4. **Safety:** default-deny external, financial, legal, employment and irreversible actions; require human approval.
5. **Transparency:** show real status, last successful execution, errors, connected services, usage and charges. Never show simulated activity as live work.
6. **Privacy:** isolate each business, minimize collection, encrypt data, define retention, and support export/deletion workflows.
7. **Recovery:** provide safe retries, human escalation, clear incident messages and a way to resume after interruption.
8. **Accessibility:** target WCAG 2.2 AA, keyboard navigation, readable contrast, screen-reader labels and responsive mobile layouts.
9. **Language:** use the user's chosen language for core workflows, support, consent, billing and safety notices. Legal/commercial translations require native review.
10. **Support:** provide a human contact path for billing, privacy, security and failed critical workflows.

A feature fails acceptance if it is technically functional but opaque, coercive, difficult to revoke, or hides the real execution state.
